# 08 · 构建、烧录与运行

## 1. 工具链与环境

| 项目 | 值 | 来源 |
| --- | --- | --- |
| 编译器前缀 | `riscv-nuclei-elf-` | `utils/common_head.mk` |
| 架构 | `rv32imafc` | `project_file/makefile` |
| ABI | `ilp32f` | 同上 |
| 代码模型 | `-mcmodel=medlow` | 同上 |
| 优化 | `-Os` + `-flto` | `common_head.mk` / makefile |
| 构建辅助 | `busybox`、`lua.exe` | `tools/build-tools/bin` |
| 打包工具 | `ci-tool-kit.exe` | `tools/` |
| 音频工具 | `lame`、`wav_to_adpcm`、`group_merge.exe` | `tools/` |

VS Code 的 `.vscode/tasks.json` 已封装：

- `clean` → `make clean`
- `compile` → `make -j<线程数> --output-sync=recurse`

两者都会把 `tools/build-tools/bin` 与编译器路径加入 `PATH`，并设置 `PROJECT_NAME`。工程选择由 `ci-tool.pick-project` 命令写入配置。

## 2. 工程构建结构

```
projects/<project>/
├── project_file/
│   ├── makefile          # 工程主 Makefile
│   └── source_file.prj   # 源文件/头文件搜索清单
├── lds/
│   ├── ci130x_asr_alg_mcu.lds        # 生成后的链接脚本
│   └── ci130x_asr_alg_mcu_temp.lds   # 模板，含 @@...@@ 占位符
├── app/                  # 应用源码
└── firmware/             # 模型、提示音、分区配置与打包脚本
```

### 2.1 `source_file.prj` → `source_file.mk`

`utils/common_tail_mcu.mk` 中定义：

```make
build/source_file.mk: source_file.prj
	$(LUA) $(SDK_PATH)/utils/generate_makefile.lua source_file.prj
```

Lua 脚本扫描 `source_file.prj` 中的目录/文件模式，生成实际的 `SRC_FILES` 与 `INC_DIRS`。新增 `.c` 文件后若未被编译，先检查该文件是否在扫描范围内。

### 2.2 编译选项

```make
C_FLAGS += -march=rv32imafc -mabi=ilp32f -mcmodel=medlow \
           -msmall-data-limit=8 -msave-restore -mfdiv $(O_OPTION) -flto
C_FLAGS += -fsigned-char -ffunction-sections -fdata-sections -fno-common \
           -fno-delete-null-pointer-checks -fno-unroll-loops -g \
           -std=gnu11 -MMD -MP
C_FLAGS += -DCI_CONFIG_FILE=\"user_config.h\" -DCORE_ID=0 -fshort-enums
```

| 选项 | 作用 |
| --- | --- |
| `-msave-restore` | 减小代码体积 |
| `-mfdiv` | 使用硬件浮点除法 |
| `-flto` | 链接期优化，跨文件内联/裁剪 |
| `-ffunction-sections -fdata-sections` | 配合 `--gc-sections` 删除未用代码 |
| `-fshort-enums` | 枚举按最小类型存储，节省 RAM/Flash |
| `-DCORE_ID=0` | 标识 HOST 核；BNPU 工程为 1 |

链接阶段还有大量 `--wrap`（`memcpy`、`malloc`、`str*`、数学函数等），用于替换为芯片优化实现或做统计。

### 2.3 算法库联动

Makefile 根据 `user_alg_config.mk` 选择库：

```make
ifeq ($(USE_BF),1)
LIBS += -lasr_host_use_deepse_v2
else
LIBS += -lasr_host_dis_deepse_v2
endif
```

压缩格式：

| `AIOT_AUDIO_COMPRESS_TYPE` | 链接 |
| --- | --- |
| 1 | `-lspeex` |
| 2 | `-lopus` |
| 3 | `-DAIOT_AUDIO_COMPRESS_BY_G722=1` |

BNPU 侧规则：

```make
$(BNPU_ALG_LIB_FILE): ../../../../system/user_alg_config.mk
	$(LUA) parse_user_alg_config_mk.lua check
	$(LUA) parse_user_alg_config_mk.lua sync
	$(MAKE) -C components/bnpu_core_alg_pro/project_file clean
	$(MAKE) -C components/bnpu_core_alg_pro/project_file
```

因此：**改了 `user_alg_config.mk`，下一次 make 会自动重建 BNPU 算法库**。这是最容易忽略的联动点。

### 2.4 链接脚本生成

`lds/ci130x_asr_alg_mcu_temp.lds` 中含占位符：

```
@@SDK_ALG_PRO_SRAM_HOST_END_ADDR@@
```

构建时 Makefile 从 `utils/common.lds` 提取 `SDK_ALG_PRO_SRAM_HOST_END_ADDR` 的值，用 `sed` 替换生成 `ci130x_asr_alg_mcu.lds`。

该符号决定 HOST SRAM 与 BNPU 算法 SRAM 的分界。修改算法 SRAM 预算后必须确认链接脚本已重新生成，否则会出现“链接不报错但运行踩内存”。

## 3. 构建流程

```mermaid
flowchart TB
    A[make] --> B[include user_alg_config.mk]
    B --> C{BNPU 配置变化?}
    C -->|是| D[parse_user_alg_config_mk.lua check/sync]
    D --> E[编译 bnpu_core_alg_pro]
    E --> F[生成 BNPU 算法库]
    C -->|否| F
    B --> G[lua generate_makefile.lua]
    G --> H[build/source_file.mk]
    H --> I[编译所有 .c → .o]
    F --> J[生成 LDS]
    J --> K[链接 build/&lt;PROJECT_NAME&gt;.elf]
    I --> K
    K --> L[objcopy → firmware/user_code/[0]code.bin]
    L --> M[复制 BNPU 库为 [1]code.bin]
    M --> N[ci-tool-kit merge user-file]
    N --> O[user_code.bin]
```

### 3.1 产物

| 产物 | 路径 | 说明 |
| --- | --- | --- |
| ELF | `project_file/build/<PROJECT_NAME>.elf` | 含调试符号 |
| HOST 镜像 | `firmware/user_code/[0]code.bin` | objcopy 生成 |
| BNPU 镜像 | `firmware/user_code/[1]code.bin` | 算法库拷贝 |
| 合并镜像 | `firmware/user_code/user_code.bin` | 合并后删除 `[1]code.bin` |

### 3.2 干净构建

```powershell
cd projects/offline_asr_llm_aiot_uart_sample/project_file
make clean
make -j8
```

`make clean` 会清理 `build/` 与中间产物，但不会删除 `firmware/` 下的模型与提示音。

## 4. 固件打包

完整固件不是一次 make 就能得到，需要按顺序执行 `firmware/` 下的脚本：

### 4.1 `合成分区bin文件.bat`

| 步骤 | 命令/动作 | 产物 |
| --- | --- | --- |
| 1 | 校验 `asr/*` 文件头是否为 `ver-1000` | 防止模型版本错误 |
| 2 | `ci-tool-kit merge asr-file -i asr` | `asr.bin` |
| 3 | `ci-tool-kit merge nn-file -i dnn -a asr` | `dnn.bin` |
| 4 | 调用 `user_file/cmd_info/cmd_info.bat` | `[60000]cmd_info.bin` |
| 5 | `ci-tool-kit merge user-file -i user_file` | `user_file.bin` |
| 6 | wav → MP3/ADPCM/PCM/FLAC/Opus，并合并 | `voice.bin` |

音频格式由脚本中的 `fmt` 变量决定（当前为 `4`，即 MP3）。

### 4.2 `打包升级.bat`

把各分区 bin 按 `config.ini` 组装为可升级固件（通常输出到 `[UPDATE] firmware-path` 指定位置）。

### 4.3 `烧录user_code.bat`

仅烧录用户代码区，适合频繁调试；使用 `code_program.exe` 通过串口写入，不重刷模型/提示音。

## 5. Flash 分区与容量约束

`firmware/config.ini` 当前值：

```ini
flash_size=2
NV_addr=0x1FC000
NV_size=0x4000
user_path=./user_code/user_code.bin
user_size=0x3F000
command_addr=0x3B000
command_size=0x2000
module_addr=0x3D000
module_size=0x132000
voice_addr=0x16F000
voice_size=0x3A000
user_file_addr=0x1A9000
user_file_size=0x2000
code1_size=0x37000
code2_size=0x24000
code2_state=False
```

三条硬约束：

1. 每个分区的 `*_size` ≥ 对应 bin 的实际大小，否则报 `partition overflow`。
2. 所有分区预留之和 ≤ NV 起点 `0x1FC000`，否则 NV 区被顶出 flash。
3. 改 `*_addr` 不会改变实际排布；真正起作用的是 `*_size` 的顺序累加。

详细推导与一次“固件超 2 MB”的实测复盘见 [CI1302 开发配置文件与 Flash 分区说明](../../CI1302_开发配置文件与Flash分区说明.md)。

## 6. 烧录方式

| 方式 | 工具 | 适用 |
| --- | --- | --- |
| 串口烧录用户代码 | `code_program.exe` / `烧录user_code.bat` | 日常调试 |
| 串口烧录整包 | `PACK_UPDATE_TOOL.exe` / 打包升级产物 | 首次生产、模型/提示音更新 |
| 云端 OTA | `CIAS_OTA_*` / `DL_*` | 量产设备升级 |
| 调试器 | OpenOCD + GDB（VS Code `launch.json`） | 断点、寄存器、内存 |

### 6.1 烧录前检查

- 芯片型号与 `config.ini` 的 `chipid=CI1302` 一致。
- 串口驱动、波特率、复位方式正确。
- 固件版本号（`soft_version_*`）已递增。
- 若启用双 Code，确认目标区 `code1/code2` 的 size 足够。

### 6.2 启动日志

上电后 UART0 输出 SDK 版本、Heap、主频，随后是各组件初始化日志。若日志停在某一行，可对照 [03-启动流程与运行时](03-启动流程与运行时.md) 的 `task_init()` 顺序定位。

## 7. 调试手段

| 手段 | 位置 | 用途 |
| --- | --- | --- |
| 分级日志 | `components/log/` | `ci_loginfo/warn/err`，按模块等级过滤 |
| FreeRTOS CLI | `components/assist/cli/` | 查看任务、内存、寄存器 |
| SEGGER SysView | `components/assist/SEGGER/` | 任务切换/中断时序可视化 |
| RTT | `SEGGER_RTT.c` | 不占 UART 的日志通道 |
| 任务监控 | `components/sys_monitor/ci_task_monitor.c` | 栈水位、运行统计 |
| 耗时统计 | `components/assist/debug_time_consuming.c` | 函数/流程耗时 |
| OpenOCD | `.vscode/launch.json` | 断点、单步、内存查看 |

### 7.1 日志配置

```c
CI_LOG(level, module_level, "fmt", ...)
```

- `CONFIG_CI_LOG_EN` 总开关。
- `SDK_RELEASE_EN` 为 1 时日志被裁剪。
- 颜色输出依赖终端支持 ANSI。

### 7.2 常见构建错误

| 错误 | 原因 | 处理 |
| --- | --- | --- |
| `undefined reference to rc_callee_*` | BNPU 侧未实现对应远端函数 | 检查 `bnpu_core_alg_pro` 与 `REMOTE_CALL` 声明 |
| `region ... overflowed` | SRAM/LDS 预算不足 | 调整 `user_alg_config.mk` 或裁剪功能 |
| `partition overflow` | 分区预留小于 bin | 增大 `config.ini` 对应 `*_size` |
| `NVdata 分区地址超出 flash` | 分区总预留超过 `0x1FC000` | 缩减 DNN/Voice/User 预留 |
| 模型格式错误 | asr/dnn 文件版本不匹配 | 使用与 SDK 匹配的模型，检查文件头 |
| `.c` 文件未编译 | 不在 `source_file.prj` 扫描范围 | 修改 `source_file.prj` |

## 8. 运行方式总结

1. **编译**：`make` 生成 HOST ELF 与 BNPU 算法库。
2. **合并用户代码**：`[0]code.bin` + `[1]code.bin` → `user_code.bin`。
3. **合成分区**：`合成分区bin文件.bat` 生成 asr/dnn/voice/user_file。
4. **打包**：`打包升级.bat` 按 `config.ini` 组装整包。
5. **烧录**：调试用 `烧录user_code.bat`，量产/整包用 `PACK_UPDATE_TOOL.exe`。
6. **启动**：Bootloader → 分区表 → HOST `main()` → `task_init()` → FreeRTOS 常态。
7. **交互**：本地唤醒/识别 → UART1 上传 → 云端 → 回传音频 → 解码播放。
